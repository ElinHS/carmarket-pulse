# 每月更新指南

給 Claude Code 的標準交辦方式。每月拿到資料後，貼下面的「交辦話術」+ 檔案路徑即可，
Windows / Mac 皆適用（Mac 只是預覽指令不同，見 README）。

---

## 一、交辦話術（複製這段，填月份與路徑）

```
更新 <O> 月資料。動手前請先 git pull 確保是最新版，改完先開本機預覽讓我確認、
我說 OK 再推 GitHub。以下是這個月的來源檔：

- 掛牌數（含競品四戰場）：<貼上 2026掛牌數_RAW+競品對戰分析.xlsx 路徑>
- 促銷方案：<貼上 2026競車促銷方案.xlsx 路徑>
- Nielsen 數位廣告：<貼上 Nielsen 匯出檔路徑，或說「這個月沒有」>
- 車市銷售觀察：<貼上文件路徑，或說「這個月沒有」>
- 社群聲量 Opview：<貼上匯出檔路徑，或說「這個月沒有」>

有哪份給哪份，沒有的就跳過。判斷不確定的地方先問我，不要自己猜。
```

> 提醒：來源 Excel 放在 `OneDrive - dentsu`，Mac 裝 OneDrive 用戶端登入同帳號即可取得，不放進 repo。

## 二、來源檔 → 儀表板資料檔 對照

| 來源 | 更新的檔案 | 對應頁面 |
|---|---|---|
| 2026掛牌數_RAW+競品對戰分析.xlsx | `data/registrations.js`（NISSAN RAW）＋ `data/comp.js`（競品四戰場） | 掛牌數追蹤、競品掛牌比對 |
| 2026競車促銷方案.xlsx | `data/promos.js` | 競車促銷方案 |
| Nielsen AdIntel 匯出 | `data/nielsen.js` | 數位廣告監測 |
| 車市銷售觀察（文件） | `data/intel.js` | 車市銷售觀察 |
| Opview 匯出 | `data/opview.js`（頁籤目前隱藏，有資料才恢復） | 社群聲量監測 |
| 其他品牌行動（選填） | `data/actions.js` | 品牌行動×銷量 |

新增月份時，除資料檔外通常還要在 `index.html` 補「該月頁籤按鈕」與月份陣列
（促銷 `MONTHS_AVAIL`、競品 `COMP_MONTHS`、Nielsen 月份頁籤等）——這部分交給 Claude 處理。

## 三、既定慣例（跨月保持一致，避免每月重新判斷）

**競品四戰場定義**：以 `2026掛牌數_RAW+競品對戰分析.xlsx` 的「級距對戰」工作表為準，
`data/comp.js` 必須與之一致。四戰場＝① 小型SUV/CUV（Kicks）② 中型房車（Sentra）
③ 國產中大型SUV（X-Trail 汽油版）④ 進口中大型SUV（X-Trail e-POWER）。

**促銷方案的固定拆併規則**（Excel 車型列與儀表板不完全一對一時）：
- X-Trail：Excel 常把「車側影像」「e-POWER 電池保固」併在汽油版格 → 汽油版放車側影像、e-POWER 放電池保固。
- RAV4：Excel 分汽油／油電兩列 → 儀表板單列 RAV4，合併為兩行顯示。
- C-HR / Prius PHV 這列：沿用歷史，納入 Corolla Sport 的方案。
- 未列入追蹤：HYUNDAI IONIQ 6、TOYOTA Camry（如要新增另行告知）。
- 該月空白的車款填 `'—'`；方案內多項以 `\n` 分行（沿用既有寫法）。

**Nielsen 花費單位**：各月花費金額只需「同月內一致」，跨月一律以份額（SOV%）比較，不比絕對金額。

**異常值備註**：停產／大改款交替／促銷暴增等，務必在 `comp.js` 該車款的 `note` 欄註明
（競品明細表會自動標 ⚠ 並顯示 tooltip），避免 MoM 暴衝數字被誤讀。

## 四、每次更新的流程檢查點

1. **先 `git pull`**（或請 Claude 先抓最新版）——確保基底是最新，避免多環境／多對話覆蓋。
2. 改對應 `data/*.js`（＋ `index.html` 月份頁籤）。
3. **開本機預覽**（`python3 -m http.server 8000` / Windows 同）確認畫面與數字。
4. 使用者確認 OK 後才 `git commit && git push`。
5. GitHub Pages 自動部署，等 CDN 更新（最長約 10 分鐘）後開線上版按 Ctrl/Cmd+F5 檢查。
